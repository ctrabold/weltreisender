# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Hugo travel blog of a bicycle trip from Germany to Singapore (2009–2010), built with the
[hugo-book](https://github.com/alex-shpak/hugo-book) theme (git submodule in `themes/hugo-book`)
plus Hugo modules `hugomods/shortcodes` and `hugomods/images` (see `go.mod`). Deployed to GitHub
Pages at `https://ctrabold.github.io/weltreisender` via `.github/workflows/deploy.yml` on push to `main`.

## Commands

```shell
# local dev server with full rebuilds (from README)
hugo server --disableFastRender --cleanDestinationDir=true --logLevel=debug --gc -M

# production build as in CI
hugo --minify --baseURL="https://ctrabold.github.io/weltreisender"

# after a fresh clone
git submodule update --init --recursive
```

There are no tests; verify changes with a local build/server. `--printPathWarnings` lists path clashes on demand;
it bypasses `ignoreLogs`, so it always shows the expected duplicate image paths of both languages.
CI (`deploy.yml`) and local development both use Hugo `0.169`; use current APIs (`hugo.Data`,
`Image.Meta`) instead of deprecated ones (`.Site.Data`, `.Exif`).

## Content structure

- `content/` — German (default language `de`). `content.en/` — British English (`en`).
  Both are configured as separate `contentDir`s in `hugo.toml` under `[languages]`.
- Diary entries are **flat Markdown files**: `content/docs/<year>/<month>/<yyyy-mm-dd>[a|b].md`
  (suffix letter for multiple entries per day).
- Section indexes (`docs/<year>/_index.md`, month `_index.md`) contain only front matter plus
  `{{<section>}}`; ordering in menus and section lists is by `date` ascending
  (overrides in `layouts/_partials/docs/menu-filetree.html` and `layouts/_shortcodes/section.html`).
  Other top-level sections: `docs/vorbereitung`, `docs/rueckblick`, `posts/` (tag overview).
- URLs drop the `docs/` section (`[permalinks]` in `hugo.toml`; files stay in `docs/` for the
  hugo-book menu): `vorbereitung/vorfahrt.md` → `/vorbereitung/vorfahrt/`. Diary `slug` = day plus
  suffix letter (`2009-05-21a.md` → `/2009/05/21a/`, English `/en/2009/05/21a/`). `aliases` keeps
  every earlier URL as a redirect (`/docs/2009/05/2009-05-21a/`, `/docs/2009/05/21a/`,
  `/docs/vorbereitung/vorfahrt/`). Slug and aliases are derived from the file path by
  `normalize_frontmatter.py` (never edit by hand; extra aliases you add are kept).
- Front matter is always YAML (`---`). German diary posts always carry, in this order: `date`,
  `title`, `slug`, `aliases`, `draft`, `summary`, `location` (lat/long and place names), `travelMode`, optional
  `route`, the day datasheet `mood` (terrible|bad|neutral|good|great, default `neutral`),
  `sleeping` (tent|hostel|hotel|homestay|vehicle|misc) and `costs` (EUR; empty = unknown), then
  `tags` and `categories`. English diary posts have only `date`, `title`, `slug`, `aliases`, `draft`, `summary`,
  `tags`, `categories`; other pages add `translationKey`, section indexes the `book*` settings.
  `uv run scripts/normalize_frontmatter.py` (dry run; `--apply` writes) adds missing keys with
  defaults, sorts them (a key moves together with its comment) and lists invalid settings (types,
  allowed values, coordinates, date vs file name, missing German/English twin). Run it after
  adding or editing pages.
- The German `location` front matter is the single source of truth for coordinates.
  `layouts/_partials/docs/location.html` (hooked in via `docs/inject/content-after.html`) renders
  the "Ort / GPS" text (labels from `i18n/*.toml`) and a Leaflet map below each post; English
  pages without their own `location` fall back to the German translation's.
- The map also draws the leg from the previous diary location, read from
  `data/routes/<year>/<month>/<post>.json`. These files are generated by
  `uv run scripts/build_routes.py` (BRouter, cached; re-run after changing coordinates or
  `travelMode`). Optional front matter `travelMode`: `bike` (default), `foot`, `bus`, `car`
  (routed), `kayak` (routed along rivers), `train`, `boat`, `plane`, `unknown` (dashed straight
  line) or `static` (no leg).
  Optional front matter `route:` (list of `[lat, lon]` waypoints: start, via points,
  finish) replaces the automatic leg with the route of the day — also works for the first post
  (example: 2009-05-01). Routed `bike`/`foot` legs also store an `elevation` profile, shown as a collapsible
  SVG below the map. A YAML comment after `travelMode` holds the evidence; `# CHECK location:` comments
  mark coordinates still to be verified by the author — keep them until the author resolves them.

## Images

- The originals (print source, untouched) live outside the site, by default
  `~/Pictures/hugo-assets-images/<year>/<month>/<day>/` (override with `SRC=`). The folder is derived
  from the EXIF capture date (`DateTimeOriginal`), which has been corrected for all new images.
  Hugo only sees the web copies in `assets/images/<year>/<month>/<day>/<name>.webp` (1600 px, the
  "large" view) and `assets/images/thumb/<same path>.webp` (400 px). Post links such as
  `/images/2009/06/01/x.jpg` keep naming the original; the site serves its `.webp` copy.
- The old `/photos/<hash>.jpeg` files (wrong date stamps) were deleted in commit `6882f0b`; all
  references are rewritten (only in git history: `git show 6882f0b^:assets/photos/<hash>.jpeg`).
- `{{< gallery from="YYYY-MM-DD" to="YYYY-MM-DD" >}}` shows all photos of those day folders;
  `{{< gallery tag="A, B" >}}` collects the gallery days and inline `/images/…` of all posts with
  those tags. Ranges are always explicit (no automatic rule). Thumbnails 400 px and large view
  1600 px WebP (PhotoSwipe lightbox); styles in `assets/styles/custom.css`. Print/book output must
  use the originals (the 1600 px copies are enough for an on-demand PDF).
- The web copies are pre-generated, not made by Hugo: `scripts/make-web-images.sh` (rush + magick +
  exiftool, incremental, `--force` to redo) turns the originals into `assets/images/…` as above
  — upright; the large copies keep all metadata (IPTC caption/keywords move to XMP), the thumbnails
  none (q65, half the size). Run it after adding or
  changing photos, then `scripts/make-web-images.sh --check` (exit 1 if an original has no copy; a
  photo without a copy is silently missing on the site). Metadata warnings go to
  `assets/images/exiftool-warnings.log`; the tool is `exiftool-rs` (Perl `exiftool` as fallback).
  Inline `![](/images/…)` images use the large copy via `layouts/_markup/render-image.html` (no
  options like `?width=` or `#center` supported there; other images fall back to the hugomods hook).
  Orphaned copies are reported, never deleted. `assets/images/` is not under version control (yet).
- Tag pages (not categories) show all photos from the time the tag covers (first to last tagged
  post, every day folder), grouped by post (`docs/tag-photos`; photos of same-day posts a/b/… go to the first one, so every
  photo appears once). One lightbox runs across all groups of a tag page; a post's own grids
  are separate lightboxes. `{{< photo-overview tags="…" >}}`
  (`content/bilder.md`, `content.en/pictures.md`) shows one tile per country. All grids render
  via `docs/gallery-grid`. Flickr links are replaced by internal ones (record: `flickr-ref.txt`);
  only `rueckblick/erfahrungen.md` and other users' photos still point to Flickr.
- `layouts/_shortcodes/map-route.html` draws a Leaflet/OSRM route
  (`startLat`, `startLon`, `endLat`, `endLon`, `mode` = foot|bike|car).
- `{{< trip-profile >}}` (homepage, below the quote; `docs/trip-profile` partial) draws the height
  profile of all bike legs as one static SVG: x = ridden km, every leg is a link to its post.
  Legs of other modes and bike legs without `elevation` in `data/routes` are left out.
- `{{< trip-metrics chart="distance|km|ascent|mood|temperature" >}}` (`content/daten.md`,
  `content.en/data.md`; partials `docs/trip-metrics` and `docs/trip-metrics-data`) draws one
  static SVG per chart over the trip days, from routes, weather and `mood`. Temperature dot: the
  low if the day's mean is below 14 °C, the high above 20 °C, else the mean.
- After the map and height profile of each diary post `docs/datasheet` shows the day data as cards: country (flag emoji + Wikipedia link, names from `data/countries.json` — add new countries there), weather, day-of-trip progress bar, country, the stage since the
  previous entry (km, days, ascent, highest point), km ridden so far (both from `docs/trip-stats`,
  cached once per language, keyed by the German file path), weather and the `mood`
  (always shown, `neutral` as 😐), `sleeping` and `costs` (one tile). Hovering the height profile under the map moves a dot along the route on the map (`docs/location`). Weather comes from `data/weather/<y>/<m>/<post>.json`,
  written by `uv run scripts/build_weather.py` (Open-Meteo/ERA5 archive, cached, only fetches new or
  moved posts; credit line CC BY 4.0 is part of the datasheet). Re-run it after changing a location.

## Translation (German → British English)

- Each English file mirrors the German file's path in `content.en/` exactly — Hugo links
  translations by identical relative path. Never rename or move a file in only one language.
- English pages get English URLs via a `slug` front matter field (e.g. `vorbereitung` → `preparation`).
- Translate `title`, `summary`, body text and `tags`; keep `date`, `draft`, `location` and
  shortcodes/link targets unchanged. Date titles follow British format
- `glossary.md` (repo root) is the translation style guide: tag mappings, section/file names,
  recurring terms and tone rules (native British English, not literal). Read it before
  translating; add new tags/terms there first so they can be reverted by search and replace.
- Diary posts mirror the German path exactly (`content.en/docs/2009/11/2009-11-14.md`) — Hugo
  links translations by identical relative path. Never rename or move them in only one language.
- Non-date pages (tags page, `vorbereitung`, `rueckblick`) get English file/directory names and a
  shared `translationKey` in both language versions (mapping in `glossary.md`).
- English files omit `location`, `travelMode`, `# CHECK` comments and the hand-written
  `Ort:`/`GPS:` footer; the template takes them from the German page.
- Translate `title`, `summary`, body text and `tags`; keep `date`, `draft`, image paths, links and
  shortcodes unchanged. Date titles follow British format
  (`Samstag, 14 November 2009` → `Saturday, 14 November 2009`).
- Untranslated pages simply don't exist in the English menu, so translation can ship
  incrementally. Language-specific settings (title, locale, `menus.after`) live under
  `[languages.en]` in `hugo.toml`. `ref` links in English pages must point to pages that exist
  in English, or the build fails.

## Conventions

- i18n: one string per sentence/tile with named placeholders fed by the template, e.g.
  `i18n "datasheet.stageBike" (dict "km" …)` and `{{ .km }}` in `i18n/*.toml` (not `%s`: names survive
  reordering in translations). Never compose a sentence from several keys; HTML in a string needs `| safeHTML`.
- Commit messages follow Conventional Commits (template in `.gitmessage`), e.g.
  `feat(hugo): …`, `fix: …`, `chore(assets): …`.
- Stop after each step and allow the user to review and commit the changes. Aim for atomic commits.

## Communication & Execution Style

- Be concise and direct. Skip preambles, apologies, and trailing summaries.
- If a task has ambiguous requirements or architectural trade-offs, ask clarifying questions before writing code

## Tooling & Environment

- Prefer local CLI tools managed by `mise` (`rg`, `jq`, `uv`, `gh`) over custom scripts.
- Never commit secrets, modify git history destructively (`push --force`, `reset --hard`), or touch files outside the workspace root.
- Never delete files. Mark them as obsolete, but let the author decide when it's time to let them go.

## Definition of Done

- Before finishing any file modification, run lint steps if available.
